# AI usage

ETHGlobal asks every team to document how AI tools were used, file by file. This file is that record, kept up to date with each commit.

| File or folder | How AI was used | What the team did |
|---|---|---|
| `README.md`, `AI_USAGE.md`, `.gitignore` | Drafted with an AI coding assistant from the team's plan | Team wrote the plan and reviewed the text |
| `android/` build setup and `MainActivity.kt` shell | Scaffolded with an AI coding assistant, modelled on the team's earlier Kotlin app setup | Team chose native Kotlin over a web app after testing NFC on the phone, and reviewed the build |
| `android/.../Nfc.kt`, `MainActivity.kt`, `Ui.kt`, `Voice.kt`, `Api.kt` | Written with an AI coding assistant from the team's flow (badge, parcel tap, receiver badge, lid photo, verdict) | Team designed the handoff flow and the Hindi prompts, tested NFC and the screens on a real phone |
| `web/lib/zg.ts`, `web/lib/hedera.ts`, `web/lib/arkiv.ts`, `web/app/api/handoff/route.ts`, `web/scripts/*` | Written with an AI coding assistant against the sponsors' SDK docs | Team designed the verdict rules (green, held, unchecked), the safe-stop and what goes on chain, and ran the HCS topic setup on testnet |
| `web/lib/arkiv.ts` (Arkiv as the database), `web/lib/payout.ts`, `web/app/api/track/*`, `web/scripts/setup-money.mts` | Written with an AI coding assistant against the Arkiv and Hedera SDK docs | Team designed the money model (dINR with a 2% network-enforced fee, escrow, payout scheduled at booking and signed at delivery, split by km) and ran it on testnet |
| `android/.../Where.kt`, GPS fields in `Api.kt` and `web/app/api/handoff/route.ts` | Written with an AI coding assistant | Team proposed paying drivers by distance and using location as proof; team chose distance over time and the 500 m stand check |
| `web/app/page.tsx` (dashboard), `web/app/track/*` (tracking page), `web/app/api/consignments`, `web/lib/ui.ts`, shadcn components | Written with an AI coding assistant; shadcn/ui components from its CLI | Team set the content (plain words for retailers, proofs one tap away for operators) and checked both pages at phone and desktop widths |
| `web/lib/agent.ts`, `web/app/api/pack`, pack mode in `MainActivity.kt` | Written with an AI coding assistant | Team designed the shop flow: tap a new parcel, the shop's agent pays for the booking over x402, tap again to write the tracking link |
| `web/lib/upi.ts`, `web/lib/settle.ts`, `web/scripts/cashout.mts` | Written with an AI coding assistant against Razorpay's Payouts docs | Team decided drivers are paid in rupees on UPI, with dINR redeemed one for one and both references logged on Hedera |
| `web/lib/history.ts`, `web/app/api/driver/*`, Bachat in `web/lib/settle.ts`, Daak meter in `web/app/api/book/route.ts` | Written with an AI coding assistant | Team designed the Bachat pot, the credit rule (25% of 30-day proven earnings, clean record, Rs 5,000 cap), the per-km meter (Rs 5 + Rs 0.50/km) and the idea that work history is read only from the public Hedera log |
| `video/` (explainer: script, spec, scenes, storyboard) | Scenes generated with an AI coding assistant and the HyperFrames skills from the team script | Team chose the storyline (dak riders into bus drivers, one parcel journey), wrote and approved the lines, reviewed the stills |
| `web/lib/swarm.ts`, `web/app/api/photo/*`, `web/app/api/drivers`, `web/app/drivers`, money view in `web/app/page.tsx`, deferred writes in `web/app/api/handoff/route.ts` | Written with an AI coding assistant | Team decided photos are evidence that must be encrypted, chose to seal the Swarm reference on Arkiv, asked for a drivers marketplace page and a faster handoff |
| `web/lib/zgstore.ts`, `web/scripts/setup-0g.mts` | Written with an AI coding assistant against the 0G Storage SDK README | Team decided every checkpoint decision, including the safe-stop ones, goes to 0G Storage as the episode log |
| `web/app/api/recheck`, provider discovery and time budget in `web/lib/zg.ts`, Recheck button | Written with an AI coding assistant | Team decided not to block on the 0G outage: cap the wait, keep the safe-stop, and let unchecked handoffs resolve themselves when 0G is back |
| Android UX pass (`Ui.kt`, `MainActivity.kt`) and `web/app/api/me`, `parcel`, `routes` | Written with an AI coding assistant | Team asked for a seamless flow per person: remembered sign-in, role-aware home, Hindi first in Devanagari, the next receiver named before the tap, the camera opening by itself, fee shown before paying, the code-on-lid instruction |
| Lifecycle backend: `web/lib/network.ts`, `web/app/api/{network,join,receivers,plan,resolve}`, `web/app/api/driver/[uid]/parcels`, booking with chosen receiver and drivers | Written with an AI coding assistant | Team asked for the whole lifecycle (joining, choosing receiver and drivers, pickup as a proven handoff, to-do lists, disputes with pay or refund, payout to each driver own UPI ID) and decided phone and UPI are sealed in the public record |
| App lifecycle (`MainActivity.kt` join form, receiver and driver choice, to-do card, handoffs from either side; `Ui.kt` Field and Choice) | Written with an AI coding assistant | Team defined who does what at each stage and asked for joining, choosing and disputes to be part of the flow |
| Security (`web/lib/auth.ts`, `web/proxy.ts`, `web/app/api/login`, guards on every money and privacy endpoint, booking cap, joined-only routes), landing page `web/app/page.tsx`, live stats, app key in the APK | Written with an AI coding assistant after a judge-perspective review the team asked for | Team decided what is public (tracking, drivers, landing) and what needs the operator or the app |
| Signed handoffs: `web/lib/signing.ts`, `web/app/api/device`, `android/.../DeviceKey.kt`, tests | Written with an AI coding assistant | Team chose to answer the custody question by having each handoff signed in the phone secure hardware, with the public key on Arkiv and the signature on Hedera |
| UPI step: `web/app/api/upi`, `web/components/upi-pay.tsx` | Written with an AI coding assistant | Team chose operator UPI with the UTR recorded on Hedera until a licensed payout partner is connected |
| Booking fee as a percentage (`web/lib/network.ts`, plan, routes, book, landing), its test | Written with an AI coding assistant | Team chose a percentage of the meter over a flat fee and agreed the build order |
| Split payout: `web/lib/split.ts`, tiers and pool in `web/lib/rules.ts` and their tests, advance and holdback in the handoff, review, recheck and resolve routes, dashboard money panel, tier on the app home | Written with an AI coding assistant | Team took the meeting insight (part pay at handover, the rest held to repay the customer) and chose tiers by record, a self-releasing Hedera schedule for holdbacks, liable-leg refunds and a capped protection pool |
| Bus number and driver KYC: `web/app/api/join`, `web/app/api/kyc`, `web/components/kyc-review.tsx`, Arkiv badge columns, app join screen | Written with an AI coding assistant | Team asked for the bus number, mobile and a government ID for driver KYC; chose driving licence first, masked Aadhaar only, last 4 characters kept, operator verifies |
| Network map: `web/app/network/page.tsx`, `web/public/map/india.json` (built from the pincode directory, OpenStreetMap bus stations and OSRM road routes), stop map positions in `web/data/network.json` | Written with an AI coding assistant | Team asked for the post office and bus network on a map, along the road rather than straight lines, and pan-India so the major hubs show |
| Full-width layout pass: landing on a 12-column grid, drivers with a record explainer, network header beside its stats, two-column tracking | Written with an AI coding assistant | Team asked for full page width and for every page to look finished in it |
| Standing orders: `web/lib/standing.ts`, `web/lib/booking.ts`, `web/app/api/standing`, `web/vercel.json`, `web/components/standing-panel.tsx`, the due-today rule and its test, app daily card and attach; the fee stored in paise | Written with an AI coding assistant | Team took the meeting insight (daily, predictable B2B volume) and chose early-morning booking by the shop's agent with a tap to attach the day's parcel |
